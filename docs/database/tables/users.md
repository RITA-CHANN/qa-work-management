# users

One row per person who can log in. Created by the seed, and since Phase 3C by a System admin in Admin console ›
Users ([API-ADMIN-04](../../api/admin/post-user.md)); there is no self sign-up (see
[requirements/auth](../../requirements/auth/README.md) and [requirements/admin](../../requirements/admin/README.md)).

## Relationships

| Column            | References / referenced by | On delete | Meaning                                                                                    |
| ----------------- | -------------------------- | --------- | ------------------------------------------------------------------------------------------ |
| `id`              | `sessions.user_id`         | cascade   | Deleting a user ends all their sessions                                                    |

## Lifecycle

- Created and updated by the seed (upsert by `email`). The seed resets `status`, `password_hash`,
  `must_change_password` and `last_project_id` of every seed user, so a test that changed them starts clean.
- Phase 3C: created by an Admin with `must_change_password = true` (BR-ADMIN-07). Admin actions change
  `global_role` (BR-ADMIN-08), `status` (BR-ADMIN-10) and `password_hash` + `must_change_password` (BR-ADMIN-12);
  [POST /api/auth/change-password](../../api/auth/post-change-password.md) sets `must_change_password = false`.
- `last_sign_in_at` is set on each successful login; `last_project_id` by
  [PUT /api/me/current-project](../../api/me/put-current-project.md).
- The API never returns `password_hash` (BR-AUTH-12).
- Never deleted by the app: an account is deactivated instead, so history keeps the name (BR-ADMIN-10).

## Retention

Kept for ever: accounts are deactivated, never deleted (BR-ADMIN-10). Deleting a row by hand also deletes their
sessions, and fails while they have audit entries.

## Data quality rules

| Rule                                        | Checked by                                                                 |
| ------------------------------------------- | -------------------------------------------------------------------------- |
| `email` is unique and lower-case            | Unique index; the API lower-cases before saving and searching (BR-AUTH-01) |
| `password_hash` is never returned or logged | `authUserSchema` has no such field; logger redaction (BR-AUTH-12)          |
| `global_role` is `ADMIN` or `USER`          | Postgres enum `GlobalRole`                                                 |
| `status` is `ACTIVE` or `DEACTIVATED`       | Postgres enum `UserStatus`                                                 |
| At least one user is an active `ADMIN`      | API checks inside the transaction (BR-ADMIN-09, `LAST_ADMIN`)              |
| A `DEACTIVATED` user has no sessions        | Deactivation deletes them in the same transaction (BR-ADMIN-10)            |
