# users

One row per person who can log in. Created by the seed only in Phase 2 (no sign-up yet, see
[requirements/auth](../../requirements/auth/README.md)).

## Columns

| Column          | Type         | Null | Default             | Key    | Definition                                                               | Classification | Rule       | Since phase |
| --------------- | ------------ | ---- | ------------------- | ------ | ------------------------------------------------------------------------ | -------------- | ---------- | ----------- |
| `id`            | text         | no   | `cuid()`            | PK     | Unique identifier of the user, generated by the API                      | internal       |            | 1           |
| `email`         | text         | no   |                     | unique | Email address the user logs in with, stored lower-case                   | personal       | BR-AUTH-01 | 1           |
| `name`          | text         | no   |                     |        | Display name of the user, shown in the header                            | personal       |            | 1           |
| `global_role`   | `GlobalRole` | no   | `USER`              |        | Role of the user across the whole app: `ADMIN` or `USER`                 | internal       |            | 1           |
| `password_hash` | text         | yes  |                     |        | argon2id hash of the user's password; `null` means the user can't log in | secret         | BR-AUTH-12 | 2           |
| `created_at`    | timestamp(3) | no   | `now()`             |        | Time the row was created (UTC)                                           | internal       |            | 1           |
| `updated_at`    | timestamp(3) | no   | Prisma `@updatedAt` |        | Time the row was last changed (UTC)                                      | internal       |            | 1           |

## Indexes and constraints

| Name              | Columns | Kind        | Why                           |
| ----------------- | ------- | ----------- | ----------------------------- |
| `users_pkey`      | `id`    | primary key |                               |
| `users_email_key` | `email` | unique      | Login looks users up by email |

## Relationships

| Column | Referenced by      | On delete | Meaning                                 |
| ------ | ------------------ | --------- | --------------------------------------- |
| `id`   | `sessions.user_id` | cascade   | Deleting a user ends all their sessions |

## Lifecycle

- Created and updated by the seed (upsert by `email`).
- The API never returns `password_hash` (BR-AUTH-12).
- Not deleted by the app in Phase 2. An admin screen comes later.

## Retention

Kept while the person is on the team. There is no delete in the app yet; deleting a row (admin screen, later
phase) also deletes their sessions.

## Data quality rules

| Rule                                        | Checked by                                                                 |
| ------------------------------------------- | -------------------------------------------------------------------------- |
| `email` is unique and lower-case            | Unique index; the API lower-cases before saving and searching (BR-AUTH-01) |
| `password_hash` is never returned or logged | `authUserSchema` has no such field; logger redaction (BR-AUTH-12)          |
| `global_role` is `ADMIN` or `USER`          | Postgres enum `GlobalRole`                                                 |
